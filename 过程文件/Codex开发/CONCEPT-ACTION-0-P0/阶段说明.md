# CONCEPT-ACTION-0-P0 阶段说明

## 范围

- 只制作 `SURF0 / JUMP_AIR / UW_NORMAL × 阳阳/爸爸` 六张静态精灵。
- 人物身份来自用户已确认的 `CONCEPT-MODEL-LOCK`；动作、镜头朝向、近远肢体与水层来自三张锁定 FC 证据。
- 本轮只有一个有证据的来源方向，不制作镜像方向，不制作动画，不接入 HTML。
- `过程文件/Kimi开发/CONCEPT-1A/` 与 `CONCEPT-MODEL-0/` 继续作为失败记录保存；本构建器不读取、不复用其像素。

## 输出

- 六张透明 PNG：`SURF0_yy.png`、`SURF0_dad.png`、`JUMP_AIR_yy.png`、`JUMP_AIR_dad.png`、`UW_NORMAL_yy.png`、`UW_NORMAL_dad.png`。
- `派生精灵审核板.png`：每张含原生 1× 与整数 3×，供用户逐张审核。
- `动作骨架板.png`：不含原版截图的动作轴线、近远肢体与动势标定。
- `concept_action_p0_manifest.json`：固定逐帧接口、PNG 元数据、调色板与哈希。
- `validate_concept_action_p0.py`：验证画布、二元 alpha、固定调色板、元数据、哈希、Git 忽略和正式游戏哈希；`--rebuild` 额外验证连续构建一致。
- `本地勿提交/`：含 FC 截图或概念图裁片的本地对照板，已具名忽略。

## 审核边界

机器验证通过只证明文件合同，不代表视觉通过。六张必须由用户逐张确认后，才能把 `reviewState` 改为冻结并交给 Kimi 扩动作库。

## 现在游戏实际长什么样

正式运行游戏仍然完全没有变化：仍是富士山泳池背景和原 FC 风格小人物。当前六张较高分辨率的概念人物只存在于静态 PNG 与审核板中，尚未进入 HTML、状态机或动画。
