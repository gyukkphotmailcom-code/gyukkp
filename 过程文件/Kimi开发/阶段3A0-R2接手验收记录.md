## R2 修复项

### 1. 废弃错误的 UW 证据

旧0基 f15625、裁剪 `(60,114,125,136)` 实际包含两名接触角色和环境像素，65×22 mask
不是单人轮廓。这是“大长条/胶囊状水下人物”的直接根因，不能靠补1px连通桥修复。

R2 改用：

- 主帧：0基 f12490，06:56.333，单人、无遮挡、源朝右
- 同景空背景：f12504
- 安全裁剪：`(129,107,163,125)`，34×18
- 人物可见 bbox：abs x130..161/y108..123，32×16
- canonical：严格 `horizontal_flip` 为 L
- 辅证：f12493 同序列另一相位；f15600 另一干净单人实例

差分结果为369px、单一4连通域；新身体、身份位置、锚点、参考图、mask、JSON和JS均按
34×18重建，旧65×22数据不再使用。

### 2. 强化独立证据链

- 三个 mask PNG 必须原始 mode=1，不能先转1位再假装输入合规。
- JSON schema固定来源SHA、帧号、frameBase、fps、裁剪框、方向、变换、recipe、像素数、
  bbox、mask SHA和原生参考裁剪SHA。
- UW另以代码锁固定前景/背景裁剪SHA、背景帧号和差分阈值。
- 原版源存在时复核源SHA；默认干净构建不要求被ignore的原版视频存在。

### 3. 修复运行时水面遮挡

旧脚本把世界 y72..101 直接交给只扫描本地 y0..29 的编码器，因此JS内30行全零；场景图
看似正确只是Python合成绕开了这个错误。

R2先把 y 转为0..29再编码，并断言：

- 30行
- 29行非空
- 3942px
- hex decode roundtrip 与源点集完全相等

### 4. 修复方向锚与JS契约

- JUMP保留真实脚底锚 L(24,41)/R(30,41)，不再把右向锚放在透明点，也不人为加宽脚底。
- UW为 L(17,9)/R(16,9)，左右 bbox 中心偏移1px。
- JS正式字段统一为 `rootByDir` / `visibleBBoxByDir`。

### 5. 修复审核图

旧审核表的所谓1×/8×会再次缩放，且尺寸不足时把8×图缩回去。R2每格：

- 左上原样粘贴严格原生1×
- 主体只做一次NEAREST 8×
- 格子按最大55×42×8预留，不执行fit
- UW身份稿使用真正的水下调色
- “真实叠加”误名改为明确的XOR/identity图
- L/R锚点分别展示

### 6. 防止失败产物覆盖

默认流程先执行全部自检；失败立即退出且不写正式产物。通过后5个输出先写临时目录，
Node语法和图片全部成功后再原子替换正式文件。

## 历史判定（已撤销）

本节原先写作“R2 已通过、可进入3A-1”；该结论已被后续原生1×盲审推翻。R2 的自动门只
比较 alpha 外轮廓，没有验证人体内部解剖、泳衣边界和唯一面部语义，因此不能作为视觉通过
依据。**R2、其 JS、审核图和精灵不得接入主 HTML，也不得作为3A-1输入。** 后续只以
`build_sprites_r3a.py` 的原版人体母版门及其新验收记录为准。

Git尚未建立R2基线；提交时必须显式逐路径暂存，禁止 `git add .`，并排除主HTML、旧Stage3、
旧3A、`build_sprites.py` 与 `build_sprites_3a.py`。
