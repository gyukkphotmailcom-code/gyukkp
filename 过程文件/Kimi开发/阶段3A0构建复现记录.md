> 内部结构和“双脸”视觉问题被撤销。不得运行其生成器覆盖 R3A 产物，不得把本记录解释为
> 可进入3A-1或可接入主 HTML。当前工作以 `build_sprites_r3a.py` 和 R3A 记录为准。

## 结论

当前 R2 默认构建退出码 0；两份只含必需输入的干净目录分别重建，5个正式输出与项目目录
逐字节一致。失败的自检会在写正式产物前退出，避免再次出现“源码失败却覆盖上一轮通过产物”。

## 环境

- Python 3.9.6
- Pillow 11.3.0
- imageio-ffmpeg 0.6.0（只用于 `--extract-refs` / `--make-mask`）
- ffmpeg 7.1（imageio-ffmpeg 自带 arm64 二进制）
- Node v24.18.0；脚本通过 `shutil.which('node')` 查找，不写死路径

## 命令

```sh
cd 过程文件/Kimi开发
.venv/bin/python build_sprites_3a0.py --extract-refs
.venv/bin/python build_sprites_3a0.py --make-mask
.venv/bin/python build_sprites_3a0.py
```

默认模式不需要原版 GIF/MP4 存在；它只需要以下可跟踪输入：

- `build_sprites_3a0.py`
- `avatar_paint.py`
- `阶段1截图.png`
- `阶段3A0参考/` 中的 mask PNG/JSON 和派生参考裁剪

原版 GIF/MP4 只用于重新生成派生证据；若本机存在，脚本会额外核验其完整 SHA-256。

来源文件/SHA、0基帧号、fps、裁剪框、方向/变换、recipe、参考裁剪SHA；UW另校验前景和
背景裁剪SHA、背景帧号和差分阈值。

## 输出契约

- JS 字段为 `rootByDir` / `visibleBBoxByDir`，无旧 `root` / `visibleBBox` 别名。
- `waterOcclusion.rows` 是相对 y=0..29 编码，`pixelCount=3942`。
- 审核表中的每个图块左上是严格原生1×，主体是仅一次NEAREST 8×。
- 5个输出先写同文件系统临时目录；全部自检、Node语法和图片生成成功后才 `os.replace`
  到正式路径。
